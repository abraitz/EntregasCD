## Ejercicio 3 - Ciclo de vida en la práctica

### Modelo de ciclo de vida

Para el desarrollo de este caso eligiría  el modelo iterativo porque los requisitos cambiarán tras recibir los feedback de los clientes piloto. Con este modelo se pueden reañizar cambios acordados con el cliente en cada iteración conforme sujan las nuevas necesidades.

### Metodología aplicada

La metodologóa ágil sería la adeacuada porque requiere mucha menos documentación para realizar seguimiento del desarrollo para futuros posibles errores, pero principalmente porque facilita los cambios en el software debido a que es una metodología flexible que no necesita seguir una estructura rígida.

### Comportamiento de operacion de actualizar estado de envío en la clase envío.

Se parte del estado inicial del envío "EN_ALMACEN", así aque se anula como valor permitido para la proxima actualización de estado de envío el valor "ALMACEN". A continuación el repartidor recoge el envío y solicita cambiar el estado de envío a "EN_REPARTO". La clase envío comprueba que sea uno de los valores permitidos ( "EN_REPARTO", "ENTREGADO" y "DEVUELTO"). La solicitud de el repartidor es uno de los valores permitidos así que acepta y actualiza el cambio de estado de un envío.
Tras está operación el valor "EN_REPARTO" tienen que quedar anulado para los próxima ctualización de el pedido, solo debe permitir introducir "ENTREGADO o DEVUELTO".
Si en alguna operación el repartidor introduce un valor que no estea dentro de los permitidos nos responde rechaza la operación y no realiza ningún cambio en el estado.
Si el repartidor introduce un valor permitido la operación es aceptata y modifica el estado por el nuevo valor.
